# 参与 Cubrim Research

[English](../../CONTRIBUTING.md) · [Русский](../ru/CONTRIBUTING.md) · 简体中文 · [概览](OVERVIEW.md)

维护的文档、议题说明和研究报告使用英语。准确保留来源引文和名称。本知识集与商业实现分离。

## 有价值的贡献

请提供具体的研究问题；带有作者、版本和日期的一手来源；相关假设；建议的方法或可复现的证据；数据与图表的权利状况；以及限制条件。说明材料属于文献综述、假设、模型、实验还是待发布候选内容。不要用精致的叙述代替缺失的测量。

文献综述应说明各引用来源实际证实了什么，以及哪些内容属于推断。只要方法与限制得到记录，未成功的实验也可能有价值。没有相应证据时，不要声称新颖性、普遍优势、实现支持或客户采用情况。

## 发布流程

草稿 → 科学与产品审查 → 技术披露及权利检查 → 获准发布的公开材料 → 网站文章。标明实际作者和贡献者；不要将所有审阅草稿的人都列为作者。保留版本历史，并将更正关联到受影响的出版物。

只有已确认具有发布权限的数据说明、图表和文本才能进入公开仓库。不要上传保密源码、尚未发布的优化设计、内部代理记录、客户信息、包含漏洞利用细节的安全研究结果或身份验证凭据。敏感材料应使用项目的非公开报告渠道。

不得自动镜像非公开仓库、共享 `.git` 历史，或不受限制地导出数据库。审查生成文件、计算笔记本和嵌入附件的实际内容，而不只看扩展名。对公开研究的贡献不授予访问非公开产品源码的权限或相关权利。

## 再利用条件

每项出版物和数据贡献都需要明确的权利与再利用记录。仓库整体的再利用许可证由所有者另行决定，不能从公开仓库的名称推定。保留第三方声明。研究文本与已编译产品的许可是不同的问题。

## 文章模板

标题；问题与背景；来源依据；方法与假设；结果或建议的实验；限制条件；对后续研究的意义；参考文献；作者与贡献者；版本与更正历史。

公开内容应清楚解释科学问题，同时不披露专有实现。在可能的情况下保留通向公开证据的链接；对访问受限的评估材料作出标注，不要发布访问令牌或内部路径。
