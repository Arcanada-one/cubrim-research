# 公开开发路线图

[English](../../ROADMAP.md) · [Русский](../ru/ROADMAP.md) · 简体中文 · [概览](OVERVIEW.md)

修订日期：2026 年 11 月 15 日。这是一项拟开展的计划，并非已完成优化的清单。现有已批准资源范围内的工作可以在融资轮次前推进；规模更大的阶段取决于已商定的团队和预算。

## 当前优先事项

在保证精确还原的前提下，加快压缩和解压缩，降低内存消耗，并简化产品分发。在选择优化方案之前，建立可复现的基线。商业实现保持非公开，经过审查的知识另行发布。

## 产品方向

### Cubrim Archiver

测量完整输出大小、编码和解码时间、CPU 开销、峰值内存，以及软件包大小和启动成本。开发最大压缩、均衡、快速和内存受限配置，并记录各自的取舍。在对照输入和此前未使用的输入上测试。随着构建和还原测试通过，扩展已验证的平台支持，包括 Linux x86-64 和 macOS arm64。

预期成果：针对特定工作负载的配置，在保持精确重建和读取旧版本数据能力的同时，改善所需的性能与资源平衡。

### Cubrim Addressor

将共享数据和引用与进一步压缩结合评估。测试更大规模的备份、版本数据与同步工作负载。计入基础数据的首次传送、索引、元数据、缺失块、更新和重传；区分首次交换与重复交换。测试查找、完整性、传输续接和独立恢复。

预期成果：在选定工作负载上测得整个系统的优势，而不是孤立地观察引用列表是否变小。

### Cubrim Web

为应用程序、服务器、API 和浏览器开发服务端与客户端流式压缩。降低编码器和解码器开销、内存需求与客户端初始加载大小。测量首次有效输出时间、完整交付、延迟分布、字典和解码器传输，以及回退行为。从可控的客户端与服务端环境起步；标准浏览器集成是单独的阶段。

预期成果：与适用的基线编解码器相比，在满足应用延迟和资源要求的范围内减少传输量。

## 跨产品计划

- **研究：** 查找一手来源、提出可检验的假设、开展非公开实现实验、记录负面结果，并发布经过审查的研究结论。
- **可靠性：** 精确还原、损坏输入处理、资源限制、兼容性测试样本、独立恢复和经过测试的回滚。
- **集成：** 文档化的 SDK、CLI 和服务器接口约定，可重复的部署、带版本的更新与支持。
- **应用推广：** 测得的客户经济效益、付费试点范围、年度许可，以及服务提供商和 OEM 集成。市场情景并非已确认收入。
- **行业研究：** 科学数据集、间歇性和远距离通信、空间站、望远镜，以及自主月球和火星系统。硬件与协议工作需要专门的需求和合作伙伴；不声称已取得飞行资格认证。

## 从获资助计划启动起计算的阶段

| 阶段 | 计划成果 |
|---|---|
| 下一个工程周期 | 明确的基线、瓶颈分析，以及范围受限的速度和内存优化候选方案 |
| 0–6 个月 | 目标性能配置、具有代表性的试验、权利与集成准备 |
| 6–12 个月 | 稳定的库或服务器模块、付费部署、更新与支持 |
| 12–24 个月 | 可重复的服务提供商和 OEM 接入流程、研究自动化与合同业务扩展 |
| 此后 | 更多数据类别、Web 集成和专门的行业计划 |

进展按成果验收，而非按日历标签认定。公开结果应标明经过测试的构建、工作负载和测量方法。初始原型不构成普遍的性能保证。
